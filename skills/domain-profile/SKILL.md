# 域名画像 / 信息采集

很多目标是**刚发现、用途不明**的域名。测试的同时，顺带把这个域名**摸清楚并记录下来**，
对 InfoSec 很有价值。本 skill 规定画像要采集什么、怎么记录。

## 什么时候做

- 场景化发起测试默认带"域名画像采集"时；
- 面对一个你还不清楚用途的域名时；
- 用户单独选择了"域名画像 / 信息采集"场景时。

## 采集清单（至少覆盖，鼓励补充更多有价值信息）

1. **用途与受众**：这个站点是做什么的？面向谁（内部员工 / 合作伙伴 / 公众）？
2. **认证**：是否需要登录？认证方式（SSO / OAuth / 表单 / Basic）？SSO 提供方是谁？是否 MFA？
   （需要 SSO 登录才能继续时，用 `authenticated-session` 技能发起人工登录接管。）
3. **数据面**：登录前 / 登录后分别能看到什么数据？是否含敏感数据（PII、财务、凭据、内部资料）？
   有无数据分级线索？
4. **技术栈 / 指纹**：服务器、框架、前端框架、CDN、WAF、语言版本。
5. **入口面**：主要功能与页面、API 面、上传点、搜索、管理后台迹象。
6. **暴露面与归属**：对外还是对内？IP 归属 / 资产信息（可调用 `portal_ip_lookup`、`portal_asset_lookup` 富化）；
   结合域名清单里的 owner / 业务线。
7. **风险初判**：显眼的配置问题、过期版本、调试信息、目录列举、默认页、泄露的注释 / 源码映射等。

## 截图取证

对关键页面用 `playwright-cli` 截图，存到任务工作目录（如 `profile/` 下），文件名见名知意：

```bash
playwright-cli open https://<target>/
playwright-cli screenshot profile/01-home.png
# 登录页、登录后主页、敏感功能页……
```

建议至少截：首页、登录页、登录后主页、任意敏感 / 高价值功能页。

## 记录为可复盘信息

把画像**记录为一条信息级发现**（用 `report_finding`，严重度用 info / 信息级，类别写 recon/画像），
正文用小标题覆盖上面的清单，并引用截图路径。这样用户能在「发现」里直接查看。
除清单项外，**主动补充**你认为有价值的观察（如这个系统像是什么业务、值得重点测的点、关联系统线索）。

## 边界

- 画像属**信息采集**，默认不做漏洞利用；是否利用、能否改数据，以本次任务的**强约束等级**为准。
- 不要把截图里的敏感数据、cookie/token 等原样写进报告正文；必要时打码或只描述。
