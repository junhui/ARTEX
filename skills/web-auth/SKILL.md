# 认证与会话安全(Broken Authentication)

认证、会话管理、凭据处理中的缺陷,导致冒充、劫持或绕过。

## 关注点

- **认证绕过**:可跳过登录直达受保护资源;"记住我"/token 逻辑缺陷;参数篡改切换身份。
- **会话管理**:登录后会话标识是否更换(会话固定)、登出/超时是否真失效、并发会话、会话标识可预测。
- **Cookie/JWT**:`HttpOnly`/`Secure`/`SameSite` 是否缺失;JWT 的 `alg:none`、弱密钥、未校验签名、`exp` 未校验、敏感信息明文。
- **口令与找回**:口令策略、找回流程的 token 可猜/可重用/越权重置、枚举用户名、OTP 校验缺陷。
- **防爆破**:是否有速率限制/锁定(**只验证机制存在性,不做大规模爆破**)。

## 白盒信号

- 登录成功后未重建会话;登出只清前端不清服务端;
- JWT 校验代码未验签或信任客户端声明的角色/身份;
- 找回 token 生成用弱随机 / 可预测 / 不过期 / 不绑用户;
- 认证中间件可被某些路由/方法绕过。

## 验证(按 ROE)

- 以**非破坏**方式证明:如伪造/篡改一个无签名 JWT 访问受保护接口成功、会话固定后用旧标识仍可用、找回 token 可重用——用最小请求对比 + 截图。
- **不做大规模爆破/撞库**;需要改他人账号口令的,`safe_validate` 下不要真改,改为证明流程缺陷(如 token 可预测)并标注。
- 只走带内。

## 严重度要点

认证绕过/会话劫持通常 High+,但看实际能冒充到谁、前提多强、波及多广。只发现 Cookie 缺 `HttpOnly` 而无实际影响,多为 Low 或到"下限"。

边界与报告规范见 `web-app-pentest/references/methodology.md`。
