# 白盒源码安全分析(code-sast)

有源码就吃到代码分析的红利:直接看不安全的数据流,而不是只靠黑盒猜。产出**结构化可疑点**
(文件:行 + source→sink + 缺失的防御 + 最小 PoC 设想),交给运行时按类别验证。

> 没有源码时跳过本 skill,走黑盒(见 `web-app-pentest`)。

## 获取源码

- 若任务已提供源码路径,直接只读分析。
- 若给了代码仓库地址且已授权,用 Bash 克隆到任务工作目录只读分析:
  `git clone --depth 1 <repo> source/`(大仓用浅克隆;只读,不改)。
- 记录你分析的**版本/commit**,报告里注明。

## 阶段(轻量版 capella 方法)

1. **校准(calibrate)**:快速过一遍仓库结构、语言/框架、入口(路由/控制器/中间件)、配置与依赖,判断这是什么系统、信任边界在哪。
2. **威胁建模(threat model)**:谁是攻击者、保护的是什么资产、哪些是高风险接口与可信输入;据此定重点。
3. **作用域路由(code-path rules)**:
   - **重点(FOCUS)**:对外可达的路由/控制器、鉴权与会话、参数解析、数据库/命令/文件/模板/反序列化/外发请求等 sink 周边、文件上传、重定向。
   - **跳过(AVOID)**:明确越界的目录(第三方 vendor、测试夹具、生成物、与网络可达面无关的脚本)。
4. **研究(research · source→sink)**:对每个重点区域,逐条追不可信输入(参数/头/体/路由/文件名)如何流到危险 sink,经过哪些清洗/校验,哪里缺防御。用 `grep`/`read` 系统地过,别漏。
5. **初筛(triage)**:把发现按"证据强度 + 可达性 + 影响"排序,滤掉明显不可达或已被防御的。
6. **确认(confirm)**:对每个可疑点,给出完整 source→sink 轨迹、sink 上下文、为什么有问题、最小 PoC 设想。
7. **去重(dedupe)**:同一根因的多个表现合并为一个。
8. **批判 + 复核(critic/review)**:自我反驳——这个数据流真的可被外部触发吗?清洗真的无效吗?把站不住的降级或丢弃。

## 持久化知识库(KB)

把白盒分析沉淀为**任务工作目录下可累积的知识库**(`sast-kb/`),让各阶段/各类别共享、避免重复、
并作为报告与去重的依据。建议结构:

```
sast-kb/
  index.md               # 总览:系统是什么、技术栈、入口清单、已覆盖/待覆盖、指向下面各文件
  THREAT_MODEL.md        # 威胁建模:攻击者、资产、信任边界、高风险接口、可信输入
  entities/<name>.md     # 关键组件/模块画像(职责、入口、依赖、数据流)
  vulnerabilities/<class>.md  # 按类别累积的可疑点与结论(injection/xss/authz/auth/ssrf)
  exploit-tasks.md       # 结构化"利用任务"清单(见下)
```

边分析边写、边更新 `index.md` 的覆盖进度(哪些目录/入口已过、还剩哪些),这样续作或他人接手时不丢上下文。

## 任务形成(task-formation)

把确认的可疑点转成**结构化利用任务**,写进 `sast-kb/exploit-tasks.md`,交给运行时按类别验证。每条含:

| 字段 | 说明 |
|---|---|
| `id` | 任务编号(如 INJ-01) |
| `class` | injection / xss / authz / auth / ssrf / other |
| `entry` | 网络可达入口(URL / 接口 / 参数) |
| `source→sink` | 代码轨迹(文件:行) |
| `hypothesis` | 攻击路径假设 |
| `poc_idea` | 最小 PoC 设想(运行时怎么触发) |
| `status` | `open` / `confirmed`(已出 PoC) / `blocked`(需带外等) / `false_positive` |
| `severity` | 仅 confirmed 时填(四问定级) |

利用阶段(`web-injection` 等)按此清单逐条验证,并回填 `status`/`severity`。

## 产出(交给利用阶段)

每条利用任务即上表一行,核心是:**类别** → 对应 skill 验证;**位置**(source/sink 文件:行);
**轨迹**(输入→经过→危险 sink + 缺失防御);**攻击路径假设 + 最小 PoC 设想**;**可达入口**。

## 边界

- 代码只读;只分析**网络可达面**能触发的代码路径(对外路由能直接/间接到达的)。
- 白盒只定位"可疑点"。要算 **exploited**,仍需在运行环境以 PoC 证明(见 `web-app-pentest` 的证据即报告);
  只能从代码推断、无法运行时证明的,如实标注"基于代码推断,未运行时证明"。
- 严重度/报告规范见 `web-app-pentest/references/methodology.md`。
